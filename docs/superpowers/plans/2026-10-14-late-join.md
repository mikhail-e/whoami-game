# Вход в начатую игру — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Новичок просится в начатую игру, любой игрок впускает его или отказывает; впущенному игроки дают персонажа.

**Architecture:** Правила запросов — чистые функции в `game-logic.js` (Jest). `server.js` ведёт сокеты ожидающих вторым `createConnectionTracker()` и пересылает события. Страница комнаты получает третье состояние «ждёт» (экран ожидания) и окно запроса для игроков; главная пропускает ответ «можно попроситься».

**Tech Stack:** Node.js + Express + Socket.IO; vanilla JS + Bootstrap 5; Jest + supertest; Playwright (Chromium, проекты `mobile` и `desktop`).

**Spec:** `docs/superpowers/specs/2026-10-14-late-join-design.md` — читать вместе с планом: события, исходы и тексты взяты оттуда.

## Global Constraints

- Ветка `feature/late-join`; перед слиянием `npm test` зелёный; спецификация и этот план уходят из репозитория перед слиянием (CLAUDE.md, «Docs hold principles»).
- Ошибки сервера — только литералами `error: '...'` / `emit('error', '...')`; новая: `This request has already been answered` → ru «На этот запрос уже ответили» в `serverErrors` (`translations-real.test.js`).
- Каждый новый текст — в `en` и `ru` (`translations.js`), ключи и строки — таблица «Тексты» спецификации.
- Данные игрока (имя, аватар) — только `textContent` / `img.src` за `isCustomAvatar()` (правило 5). Никаких `style="..."` и `on...=` (правило 8); `:hover` — только в `@media (hover: hover) and (pointer: fine)`.
- Ходы со страницы — через `sendMove()`; кто действует — игрок сокета (`playerHandler`), не ID из сообщения.
- Лимит: игроков вместе с ожидающими не больше `MAX_PLAYERS` (12).
- `io.to(список)` с пустым списком шлёт **всем** сокетам сервера — каждый вызов с массивом ID сокетов защищён проверкой на пустоту.
- Новый браузерный тест хотя бы раз ломают (docs/testing.md, правило 2); «ничего не произошло» читается один раз после точки синхронизации (правило 4).

## Review Focus

1. Двое игроков почти одновременно отвечают на один запрос → второй не видит окна с ошибкой: его окно просто закрывается (страница молча пропускает `This request has already been answered`). Тест — задача 3.
2. У ждущего новичка пропала и вернулась связь → запрос снят и подан заново, у игроков окно закрылось и открылось, новичка всё ещё можно впустить. Тест — задача 5.
3. Имя новичка с HTML-разметкой → на экране ожидания и в окне запроса оно текстом, не разметкой. Тест — задача 3.
4. Новичок ждёт в двух вкладках → «Впустить» впускает обе; закрытие одной не снимает запрос, пока ждёт другая. Тест — задача 5.
5. Впущенный без персонажа перезагрузил страницу → у него снова пустой конверт, у остальных — «+ Назначить персонажа». Тест — задача 4.
